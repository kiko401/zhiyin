## 1 产品概述

### 1.1 市场背景与问题定义

A 股个人投资者基数庞大且结构分散。截至 2025 年末，A 股投资者数量 2.51 亿（中国结算《2025 年统计年报》，一码通口径），自然人占比 99.7%；2026 年前 10 个月沪深市场新开户 2862.65 万户。结构上，账户占比约七成的 10 万元以下投资者合计仅持有个人投资者总市值的 7.6%，占比 1.84% 的百万以上账户持有 66%；多数个人投资者缺乏投顾覆盖，在信息与工具两侧处于弱势（口径见 11.4）。

该人群的投资研究行为具有两个特征。提问形态：口语化（"新易盛还能拿吗"）、黑话化（"宁王这波断板了还能拿吗"）、隐含持仓语境（同一句"还能拿吗"，被套与浮盈情境所需的答案不同）。工作流形态：研究为持续循环，包括盘中盯公告与异动、异动后查证、持仓定期体检、盘后复盘。当前市场的 AI 投研产品能力建设集中于答案生成侧，交互形态仍为问答工具：

| 玩家 | 产品动向 | 能力侧重 |
| --- | --- | --- |
| 同花顺 | 问财由自然语言问答工具向智能投研 Agent 升级，覆盖市场研究、盘中跟踪、盘后复盘、公告解读、组合分析；机构端推出 iFinD MCP（同花顺 2026 年半年度报告） | 答案生成侧 + 数据底座 |
| 阿里千问 | "深度研究"新增财经分析模块，接入同花顺超 1.3 万只股票数据、约 100 万份财报公告，Agentic 架构生成深度报告（2026-04） | 报告生成侧 |
| Kimi | 接入同花顺 iFinD、Yahoo Finance 等金融数据库（2026-04） | 通用问答 + 数据接入 |
| 腾讯 | 内测"腾讯 AI 问股"小程序，解决证券业务咨询（2026-03） | 业务问答 |
| 万得 | Wind AI 个人版上线，"智能内核、工具联动、技能分身"，机构级数据个人化（2026-03） | 工具调用侧 |
| 通用大模型直问 | 无金融工具链，数据滞后、来源不明、幻觉难控 | — |
| 通用个人智能体（Muse 等） | 任务执行范式已在生活场景验证，但不具备金融数据面、合规约束与投研工作流（见 1.2） | 生活场景任务 |

立项依据为三项判断。其一，头部厂商竞相接入同花顺数据（千问、Kimi 均已接入），答案侧供给趋于同质化，数据与模型不再构成差异点，差异化前移至输入侧：用户在问什么、语境是什么、此前问过什么。其二，2026 年消费级个人智能体范式已获市场验证：Meta 的 Muse 以任务执行为核心，上线两周登顶美区 App Store 免费榜，一个半月内获超千万用户配置（Meta 2026 年三季度财报电话会，来源见 11.4），"委托 AI 持续执行并汇报"的产品心智已被接受；但该范式在金融证券场景仍属空白，通用智能体不具备行情数据面、合规约束与投研工作流。其三，个人投资者的研究工作流（盯、查、体检、复盘）具有重复性高、耗时、数据面明确、不需要交易权限的特征，适合委托给智能体执行。

知音切入上述空缺，定位于投资者的个人研究智能体，承接用户的持续研究工作流；能力主张为：听得懂、干得完、盯得住、记得住、有分寸。

战略契合：同花顺 2026 年半年度报告明确提出"推动问财由自然语言问答工具向智能投研 Agent 升级"并输出 iFinD MCP 能力。知音以个人研究智能体形态承接个人投资者的研究工作流，其意图引擎与任务引擎为该战略路线在个人侧的落地。

### 1.2 范式对标：个人智能体的成立条件与金融变体

Meta Muse 验证了消费级个人智能体的五项成立条件。下表逐条对照知音的机制承接：

| Muse 验证的成立条件 | 知音的机制承接 |
| --- | --- |
| 替用户干活，而非陪用户聊天：产品核心为任务执行（云端虚拟机 + 浏览器），不是对话轮次 | 研究任务执行引擎（2.12）：一切交互统一收敛为研究任务，五径入口（问句、点子、委托、例行、转译）共享一处引擎 |
| 干的活看得见：执行状态实时可见（吉祥物工作动画），且分层：普通用户看状态、关注者看任务清单、工程师看日志 | 三层监看（2.12）：工作卡（过程层）/ 任务中心（任务层）/ 工作日志（审计层），全部由阶段事件渲染，前端零推算 |
| 记得住用户：跨会话记忆、偏好积累，支持"搬家"把记忆带走 | 画像 + L3 词典 + 研究档案（2.2/2.3）：字段级授权、可删可导出 |
| 不闲着：主动提议能替用户做的事（点子页）、按自身节奏产出内容（动态页）、任务关掉应用后继续跑 | 点子货架（4.2）、动态简报流（4.3）、持续任务调度（2.13）：盯盘与例行任务在后台值守 |
| 有分寸：敏感操作（支付）先停下确认；敏感信息（健康、财务细节）不主动收集 | 规格确认断点（2.5）+ 画像三条底线（2.3）；金融场景的分寸进一步为法定义务（2.8） |

金融场景的三条硬约束决定知音须做领域变体：

| Muse 的选择 | 知音的金融变体 | 差异理由 |
| --- | --- | --- |
| 云端虚拟机 + 浏览器，开放式任务域（订票、购物、回邮件） | 受证据蓝图约束的封闭任务域（盯、查、体检、复盘、扫描），数据工具面确定性映射 | 金融数据的每次调用必须可审计；开放执行体在证券场景不可解释、不可合规 |
| 毛绒吉祥物 + 拟人化陪伴，建立情感连接 | 工具性过程可见（工作卡 + 阶段事件），不做拟人化人格与吉祥物 | 投资场景的拟人化陪伴诱导过度信任、放大决策偏差，为监管与产品伦理的双重红线（1.9） |
| 支付类敏感操作前停下确认 | 决策类敏感边界前停下确认：规格确认断点 + 合规转译断点 | 金融场景的敏感边界为预测与买卖指令（R1） |
| 订阅 + 交易抽佣变现 | 生态副产品，不设独立盈利目标 | 知音的价值经主生态（问财增强、数据资产、活跃回流）兑现（1.3） |
| 通用生活数据面（邮件、日历、电商） | 双源金融数据面（扶摇九工具 + iFinD），引用四要素协议 | 进入结论的每个数字必须可回溯来源、时点、单位、口径，为命题统一规则与行业底线 |

对标结论：个人智能体形态已获消费级市场验证；知音的领域变体以可审计执行替代开放式执行，以过程透明替代情感连接，以信任资产替代付费意愿。

### 1.3 产品定位

定位语：把你的研究接过去。

知音是投资者的个人研究智能体：用户以一句话、一个点子或一条委托发起研究任务；知音理解意图（必要时澄清，澄清频次随使用递减），生成用户可确认、可编辑的研究规格，按规格调度数据工具执行，交付带来源、正反论点齐备、事实与推断分栏的研究框架；对持续委托（盯盘、例行复盘）长期值守，以简报主动汇报，重要程度由用户反馈校准。意图质量层（词典、画像、澄清、规格，第 2 章）为该形态的内核引擎。

五大能力主张（能力表述与机制的对应）：

| 主张 | 用户可感知的含义 | 机制落点 |
| --- | --- | --- |
| 听得懂 | 口语、黑话、隐含语境一次说清；说清过的不再问 | 三层词典、画像、澄清、决策器（2.1–2.4） |
| 干得完 | 委托出去的研究端到端交付，过程可见 | 任务执行引擎、证据蓝图（2.6/2.12） |
| 盯得住 | 盯公告、盯异动、盘后复盘，无需用户值守 | 持续任务、调度器、简报（2.13） |
| 记得住 | 偏好、词条、研究档案随使用持续积累复用 | 画像、L3 词典、研究档案（2.2/2.3/4.7） |
| 有分寸 | 不预测、不荐股、不替用户做决定；执行前先确认 | 合规框架、规格确认断点（2.5/2.8） |

AI Native 判定依据：判断标准不是功能列表是否包含 AI 入口，而是交互范式是否因 LLM 才成立。"一句话委托—意图澄清—规格确认—可见执行—带引用交付—持续值守—主动汇报"链路中的开放文本意图判定、歧义识别与选项生成、跨会话偏好记忆、触发动静的语义定级、多源证据归纳为正反论点框架，均为规则系统与搜索产品无法承担的环节；同时产品以确定性组件（词典、决策表、证据蓝图、任务状态机）约束模型行为边界。本产品的 AI 工程立场为：模型负责语义，规则负责边界，引擎负责过程。

生态角色：知音为同花顺生态副产品，不设独立盈利目标，不向用户收费；盈利责任由主产品（同花顺 App 及其增值业务）承担。知音对主产品的价值包括三方面：意图引擎与任务引擎能力复用于问财、AIME 助手等答案侧系统；词典、画像、澄清选择、任务与简报数据资产沉淀于生态内部；简报与盯盘服务带动日活与转化回流主产品。

产品命名取"高山流水遇知音"之义，对应"理解用户所指、可受用户托付"的产品体验。

### 1.4 LLM / Agent 的增量价值论证

本节论证各功能环节采用 LLM 的必要性边界，即哪些环节必须由模型承担、哪些环节由规则或数据工具承担：

| 环节 | 规则/搜索/人工能否胜任 | 结论 |
| --- | --- | --- |
| 高频黑话消解（宁王、断板、做T） | 词典即可，毫秒级、零成本、可审计 | 不用模型（D3/D4 词典层） |
| 清晰事实题（"茅台三季报营收多少"） | 正则 + 单工具直查即可 | 不用模型判定（D2 规则层直答） |
| 长尾问句的意图判定（口语、隐含语境、一词多义） | 规则无法穷举问法；人工投顾无法覆盖 2.5 亿用户 | 必须模型（D6 意图分类与风险分级） |
| 澄清选项生成（开放问题的选项枚举与措辞） | 模板僵硬、无法贴合语境 | 必须模型（受 D8 约束的选项生成） |
| 多源证据归纳为正反论点研究框架 | 搜索只能给出链接列表；数据产品只提供表格 | 必须模型（受 P2 契约约束的归纳生成） |
| 盯盘触发的"动静定级"（什么值得打扰用户） | 规则可做触发初筛，动静的语义严重度分级需语义理解 | 规则触发 + 模型定级（触发闸门为确定性词表与阈值，2.13） |
| 简报生成（把盯到的动静写成可读文本） | 模板拼接僵硬、无法携带语境 | 必须模型（受 P2/P3 契约约束，数字同源） |
| 工具组合规划 | 自由规划不可审计、成本不可控 | 不用模型自由规划（证据蓝图确定性映射） |

对应地，知音的执行器为计划确定性 Agent（Bounded Agent）：意图由模型判定，工具组合由证据蓝图按任务类型确定性映射，不由模型自由规划；持续任务的触发为确定性规则（词表命中、阈值穿越），模型仅负责动静定级与行文；每次调用落库留痕（tool_call、task_event 表），调用路径可回放审计。金融场景中合规与可审计优先于 Agent 自主性：模型自主性带来的灵活性收益，低于不可解释的错误输出造成的信任损失。

相对人工投顾：个性化研究的边际成本使人工服务无法覆盖长尾用户；知音通过消解、画像与任务引擎将边际成本降至近零，并以持续任务实现 7×24 值守。相对传统选股器与数据终端：用户需自行完成口语到筛选条件的转换并承担盯盘值守；知音承接该转换与值守环节。

### 1.6 产品目标与成功指标

北极星指标度量委托关系是否成立（用户是否将持续研究工作交给知音并持续使用）；机制层以少问曲线作为内核质量度量。指标体系分两层：

- **关系层（北极星）**：持续委托率，即周活跃用户中持有至少一个进行中持续任务（盯盘/例行）的比例；该指标同时约束任务创建与任务留存。
- **机制层（质量）**：少问曲线，即澄清触发率随活跃周数单调下降且回答方向正确率不降的双条件曲线，约束意图引擎的打扰水平与回答质量。

| 层级 | 目标 | 指标 | 目标口径 |
| --- | --- | --- | --- |
| 北极星 | 委托关系成立 | 持续委托率（任务持有率） | 灰度 8 周 ≥ 25%（S8，假设待验） |
| 关系质量 | 委托被续用 | 盯盘任务 7 日续用率 | ≥ 40%（S9，灰度） |
| 机制层 | 交互成本随使用下降且质量不降 | 少问曲线（双条件） | 触发率周降、方向正确率不降（H2） |

| 效率 | 主链路可用性 | 端到端延迟 / 简报时延 | 提问到回答 p95 < 30 秒（S3）；动静触发到简报可读 p95 < 60 秒 |

指标定义与验证方式见第 8 章。

### 1.8 产品原则

| 原则 | 落地 |
| --- | --- |
| 听得懂才动手 | 规格未确认不执行（2.5）；歧义处置顺序：词典可消解 → 画像可消解 → 真歧义才澄清（≤2 轮） |
| 干的活看得见 | 一切执行有工作卡（真实阶段，非动画示意）；一切产物可溯源（引用四要素）；静默消解也展示"已按词典理解为 X，可改回"；画像应用写 profile_hit 可回放 |
| 打扰有配额 | 澄清硬上限 2 轮；简报频控每日每标的 ≤ 1 条；动态页拉取为默认形态，推送通知为 V1.1 可选项且默认关闭 |
| 分寸是法定义务 | 不荐股、不预测涨跌、不给买卖指令；决策类问题转译为研究任务（R1）；不采集敏感个人信息；简报文案与推送文案同受红线约束 |
| 资产复利 | 词典、画像、研究档案随使用增值；同型问题交互成本单调下降；负反馈（"这条简报不重要"）收紧触发阈值，任务持续校准 |

| 账号体系不新建 | 复用同花顺账号（AC-01），不新增登录摩擦 |

## 2 核心机制设计

本章为 App 与 Web 原型共享的全形态规格。2.1–2.11 定义意图引擎，2.12–2.13 定义任务执行引擎与持续任务机制；全部机制按可度量、可审计、可降级要求设计。

### 2.1 问题形式化与六类歧义

一次投资提问可形式化为六元组：(标的, 语义, 口径, 周期, 语境, 意图)。任一字段不完整或不确定且影响答案方向，即为歧义。六类歧义模型（A1–A6）如下：

| 编号 | 歧义类型 | 典型示例 | 判定信号 | 首选消解路径 |
| --- | --- | --- | --- | --- |
| A1 | 标的歧义 | "宁王""中际""它呢" | 别名词典命中多候选或无候选；代词指代 | 词典 L2 → 画像 watch_list → 澄清（D10 真实候选） |
| A2 | 语义歧义 | "断板""做T""半路" | 黑话/多义词命中词典 | 词典三层消解（D3/D4） |
| A3 | 口径歧义 | "营收"（单季/累计）、"涨"（日/周/年） | 指标词多口径；时间范围缺失 | 规则默认口径 + 声明；影响方向时澄清 |
| A4 | 周期歧义 | "还能拿吗"（打板隔日 or 中长线） | 决策动词 + 周期未定 | 画像 time_horizon → 澄清 |
| A5 | 语境歧义 | "还能拿吗"（被套/浮盈/空仓） | 决策动词 + 仓位语境缺失 | 画像 risk_context → 澄清 |
| A6 | 意图歧义 | 同一句"新易盛怎么样"（要事实/要决策框架/要复盘） | 问句类型判定得分接近 | 决策器意图分类（D6）→ 澄清 |

歧义处置设两条闸门：方向影响闸门，仅当歧义会改变答案方向时允许进入澄清；消解优先闸门，处置顺序为词典消解、画像消解、澄清。

### 2.2 三层词典

| 层 | 内容 | 置信区间 | 消解方式 |
| --- | --- | --- | --- |
| L1 标准金融语 | 术语与指标的标准表述及同义集（"归母净利润"= "归属于母公司股东的净利润"） | ≥0.95 | 静默消解 + 提示条 |
| L2 社区黑话与别名 | 宁王→宁德时代（300750）、断板→连续涨停中断、做T→日内回转 | 0.70–0.95（分档：0.90–0.95 高置信 / 0.70–0.90 中置信） | 高置信静默（D3）；中置信规格确认式（D4） |
| L3 用户私有词汇 | 用户个人的代号与习惯语（"我那三只光模块"） | 用户自证 | 仅本人可见，随画像同生命周期 |

词条结构字段：词条原文、层级、标准对应、中性释义、口径注记、风险提示语（策略类词条强制）、置信度、来源与审核人、治理状态。设计约束：词典消解结果不越过规格确认断点，替换结果必须在规格卡展示且可修改。治理流程：新词提交（LX-03）→ 候选池 → 人工审核 → 灰度发布 → 线上监控回滚；用户在规格卡改回词典消解结果时写 lexicon_hit（user_override）并进入词条修正池。

### 2.3 投资者画像

字段白名单（封闭集合，不采集白名单外任何信息）：

| 字段 | 歧义类型 | 示例值 | 说明 |
| --- | --- | --- | --- |
| time_horizon | A4 | 短线 / 波段 / 中长线 | 持有周期 |
| risk_context | A5 | 被套 / 浮盈 / 空仓观察 | 定性处境，不采集成本价与仓位数额 |
| unit_pref | A3 | 亿元偏好等 | 计量与呈现口径 |
| watch_list | A1 | 标的代码列表 | 指代解析（"它/天孚呢"）；也是盯盘与例行任务的默认标的池 |
| knowledge_level | — | novice / veteran | 输出深浅与术语卡策略 |

字段来源三态：clarified（澄清确认）、declared（用户主动陈述，优先级最高）、inferred_pending（模型推断待确认，不得直接注入）。授权三态：granted（跨会话记忆）/ session_only（仅本次，默认）/ denied（该字段永不再问）。画像三条底线：不多问（非白名单不采集、denied 不再问）、不越界（不采集金融账户、身份证明、联系方式、精确资产数额）、不外传（不用于模型训练、不跨用户共享、不用于差异化定价；个保法第 24 条自动化决策可拒绝，规格卡"本次不使用画像"开关为拒绝入口）。每次画像应用写 profile_hit（字段、用途、是否接受），用户可回放（PR-03）。

画像在委托链路中的扩展应用：watch_list 为持续任务的默认标的池（"帮我盯着这几只"直接命中）；time_horizon 与 risk_context 决定简报的影响面措辞（短线用户与中长线用户对同一动静的表述侧重不同）；denied 字段不进入任务规格。

### 2.4 Clarify-or-Delegate 三层决策器

三层执行顺序为词典层 → 规则层 → 大模型层，越靠前成本越低、时延越小、越可审计；模型只处理前两层覆盖不了的语义问题。决策表 D1–D11 为纯函数（输入六元组与上下文，输出动作），可审计：

| 规则 | 判定 | 动作 |
| --- | --- | --- |
| D1 | 规则红线命中（预测/承诺/买卖指令词表） | 边界卡 + 转译任务，不消耗轮次 |
| D2 | 规则清晰命中（标的唯一 + 指标明确 + 口径可声明） | 口径声明后直答 |
| D3 | 词典高置信命中（置信 ≥0.90 且唯一映射，覆盖 L1 全部与 L2 高置信档） | 静默消解 + 提示条 |
| D4 | 词典中置信命中（0.70–0.90） | 规格确认式消解（SpecCard 高亮待确认） |
| D5 | 画像字段命中且 granted | 注入 + 来源徽章（免澄清） |
| D6 | 大模型意图分类与风险分级（意图类型 + risk_tier） | risk_tier=1 同 D1；意图分流：事实/知识/决策支持/委托 |
| D7 | 决策支持题逐项比对六类歧义清单 | 产出待澄清字段集合 |
| D8 | 存在影响方向的歧义且选项可枚举（2–4 个） | 澄清卡 |
| D9 | 澄清轮次耗尽（≥2） | 按显式假设作答，假设列于回答首段与规格卡 |
| D10 | 标的歧义需真实候选 | 调用扶摇检索返回真实候选作为选项（不生成虚构选项） |
| D11 | 意图分类判定为委托类（盯/注意/有动静告诉我/每天盘后帮我等触发词或委托意图得分最高） | 生成委托规格（trigger 四要素：盯什么/何时查/什么算动静/怎么通知），走规格确认（CH-09）；确认后创建持续任务并立即执行首次检查 |

执行序：D1 → D6（风险与意图）→ D2 → D3/D4/D5（消解）→ D7 → D8/D10（澄清）→ D11（委托分流）→ D9（兜底）。五径为决策器在五类典型输入下的标准输出：

| 路径 | 输入示例 | 行为 |
| --- | --- | --- |
| 路径一 歧义题 | "新易盛还能拿吗" | 澄清卡两轮点选 → 规格确认 → 工作卡 → 四段式回答 |
| 路径二 清晰题 | "贵州茅台 2026 年三季报营业收入和归母净利润是多少" | 不澄清，口径声明后直答 |
| 路径三 合规题 | "明天哪只股票能涨停" | 边界卡 + 转译涨停复盘任务，不消耗轮次 |
| 路径四 词典+画像题 | "宁王这波断板了还能拿吗"（同用户第二问） | 三重消解零澄清，规格卡逐字段标注消解来源 |
| 路径五 委托题 | "帮我盯着新易盛的减持公告，有动静告诉我" | 委托规格卡（trigger 四要素可编辑）→ 确认创建 → 首次检查工作卡 → 首份简报回贴对话流，任务进入值守 |

### 2.5 研究规格（Research Spec）

研究规格为澄清或消解收敛后、任务执行前的人机确认断点，用于在执行前暴露理解偏差。Schema（一次性研究示例）：

```json
{
  "spec_version": 1,
  "task_type": "decision_support",
  "ticker": {"value": "300750", "name": "宁德时代", "resolved_by": "lexicon"},
  "time_horizon": {"value": "short_term", "resolved_by": "profile"},
  "risk_context": {"value": "trapped_position", "resolved_by": "clarify"},
  "question_caliber": {"value": "现价与近 20 日区间对比口径", "resolved_by": "assumption"},
  "evidence_needs": ["snapshot", "kline", "financials", "valuation", "breadth", "capital", "news"],
  "terms": [{"term": "断板", "resolved_to": "连续涨停中断"}],
  "compliance": {"risk_tier": 0}
}
```

委托类规格扩展 trigger 四要素（Schema 节选）：

```json
{
  "task_type": "standing_watch",
  "ticker": {"value": "300502", "name": "新易盛", "resolved_by": "lexicon"},
  "watch": {
    "scope": "公告与新闻",
    "keywords": ["减持", "质押", "业绩预告"],
    "thresholds": [{"metric": "涨停梯队", "op": "enter"}],
    "schedule": "交易日每小时",
    "notify": "动态页 + 简报（推送默认关闭）"
  },
  "freq_cap": "每日每标的 ≤ 1 条"
}
```

（注：keywords 为"什么算动静"的词表，可编辑；thresholds 为阈值穿越型动静；schedule 为检查窗口；notify 为通知方式，四要素完整定义见 2.13。）

规格卡白名单字段行内可编辑：ticker、time_horizon、risk_context、question_caliber、evidence_needs；委托卡另可编辑 trigger 四要素。每次编辑确认全量落库、版本号 +1，可审计回放。resolved_by 枚举：lexicon / profile / clarify / assumption，四类消解来源徽章逐字段可见。

### 2.6 证据蓝图与双源数据面

数据面为双源架构：扶摇承担个股与标的事实面（九工具：检索、行情快照、K 线、三大报表、估值、指数成分、交易日历、涨跌停梯队、热榜），iFinD 承担市场环境与归因面（六工具：新闻、宏观、市场宽度、资金流向为 P0，政策与跨市场随 V1.1 接入）；两源按证据蓝图分工，同一证据层不重复调用。证据蓝图——任务类型到工具组合的确定性映射（非模型自由规划）：

| task_type | 典型任务 | 扶摇（事实层） | iFinD（环境/归因层） |
| --- | --- | --- | --- |
| fact_query | 财报/估值/行情事实查询 | 按指标选 1–2 工具 | —（口径声明即可） |
| decision_support | 持有体检 | 检索、快照、K 线、财报、估值 | 宽度、资金、新闻 |
| limit_up_review | 涨停复盘 | 检索、快照、K 线、涨跌停梯队、热榜 | 新闻、资金、宽度 |
| sector_review | 板块扫描 | 成分、快照、热榜 | 宽度、资金 |
| capital_perspective | 资金透视 | 检索、快照 | 资金、新闻 |
| standing_watch | 盯盘检查（触发后） | 快照、涨跌停梯队、热榜 | 新闻（含公告语义检索） |
| routine_review | 例行复盘（盘后/周度） | 同 decision_support | 同 decision_support |
| knowledge | 投资知识 | —（不取数，模型知识作答并显式标注） | — |

回答的证据按三层组装：个股事实层（扶摇）、市场环境层（iFinD 宽度/资金）、事件归因层（iFinD 新闻/宏观，政策随 V1.1）。蓝图按任务类型取用其中若干层，未覆盖层在回答"未覆盖与假设"段显式声明。引用四要素协议：进入回答与简报的每个数字与事实必须携带来源、时点、单位、口径四要素，角标 [n] 可点回（S6/G2 门禁）；两条证据冲突时并列呈现，不作裁决。数据缺失、冲突、过期或调用失败时显式标注，不静默生成"正常"结论（对应 E1/E3/E10 及 2.10 全矩阵）。

### 2.7 回答契约

回答形态分级（按 task_type）：fact_query 采用直答形态，即口径声明 + 数据事实卡（引用角标齐全，模板组装，不调模型，对应 D2 规则层直答）；knowledge 类由模型基于通识作答并显式标注"未接入实时数据，请以官方披露为准"；其余研究类（decision_support / limit_up_review / sector_review / capital_perspective / routine_review）采用四段式研究框架。四段式结构：结论摘要（不超过 80 字）/ 事实与正方论点 / 反方论点与风险 / 未覆盖与假设；折叠展开。事实与推断分色：事实蓝徽章（可溯源到证据条目）、推断灰徽章（模型归纳），两类信息不混排成一句。置信度分档（确定性规则，非模型自评）：

| 档位 | 判据（满足其一即取低档） |
| --- | --- |
| 高 | 意图字段全部经澄清/画像确认；蓝图必备工具全部成功；数据当日 |
| 中 | 存在词典消解字段；或环境层证据部分缺失（已标注） |
| 低 | 存在假设字段（D9 兜底）；或事实层部分缺口；或数据超过 90 天 |

输出校验器（服务端确定性检查，回答发出前执行）：抽取回答中的全部数字与证据条目比对，不一致触发一次重写；仍不一致按 E1 降级为证据卡。红线词表扫描通过后方可出卡（见 2.8）。

### 2.8 合规框架

| 分级 | 触发 | 处理 |
| --- | --- | --- |
| R1 硬红线 | 涨跌预测、买卖指令、收益承诺（"明天哪只能涨停""帮我决定割不割"） | 边界卡：固定话术拒绝 + 转译为可执行研究任务（如涨停复盘），不消耗澄清轮次，不作答 |
| R2 软风险 | 情绪化决策语境（"梭哈吗""要不要全仓"） | 不拒绝；作答时强化反方论点与风险段，措辞中性化，不使用情绪化呼应 |
| R3 常规 | 研究与事实类问题 | 常规作答 + 标准免责行 |

合规义务同权适用于简报与通知：简报文案、推送文案与对话回答走同一红线扫描器与输出校验器；盯盘简报只陈述已发生事实（"发布减持公告，减持不超过 X%"），不做涨跌推断与操作建议。

定性依据：产品输出始终为"研究框架与事实整理"，不构成《证券法》及证监会公告〔2012〕40 号所界定"荐股软件"功能（提供具体证券品种选择、买卖时机建议等）；全部 AI 生成内容带显式标识（《人工智能生成合成内容标识办法》）；自动化决策可拒绝（个保法第 24 条）；面向投资者风险承受能力做基础适配（参照《证券期货投资者适当性管理办法》）。监管层对资本市场 AI 应用"统筹发展与安全"的取向为本框架的依据，本框架以转译而非拒答、全程留痕、事实与推断分栏落实该取向。免责五要素固定于回答卡、简报卡与关于页：仅供参考不构成投资建议；风险提示且不承诺收益；标注来源与时点；AI 生成显著标识；不作为买卖依据、据此操作风险自担。

### 2.9 会话状态机

九态：IDLE / DECIDE / BOUNDARY / CLARIFY / MEM_NOTE / SPEC_REVIEW / EXECUTING / ANSWERED / EXPIRED。核心转移：

```text
IDLE ──提问/委托──> DECIDE ─┬─红线──> BOUNDARY ──按此研究──> SPEC_REVIEW
                            ├─清晰──> EXECUTING ──完成──> ANSWERED
                            ├─歧义──> CLARIFY ⇄（≤2轮，轮次耗尽走 D9）
                            │            │选择完成
                            │            ▼
                            │        MEM_NOTE ──> SPEC_REVIEW ──确认执行──> EXECUTING ──> ANSWERED
                            ├─可消解──> SPEC_REVIEW
                            └─委托(D11)──> SPEC_REVIEW(委托卡) ──确认──> 任务创建 ──首次检查──> EXECUTING
任一会话态 ──30分钟无活动──> EXPIRED（历史可查看、不可续问；持续任务不受会话过期影响）
```

EXECUTING 态的内部即任务状态机（2.12）：工作卡与任务中心均从 task_event 渲染，前端不推算。前端不维护状态机副本，卡片渲染按接口返回的状态与卡片类型（clarify/boundary/spec/delegate/work/answer/briefing）分派。追问作为新任务处理（轮次清零、上下文继承，继承字段在规格卡标注"继承自上一问"）。

### 2.10 降级矩阵 E1–E11

全部异常显式降级，不静默生成结论。降级横幅仅在影响主链路时出现（E1/E3/E10/E11），无感回退（E4/E5）不展示横幅：

| 编号 | 异常场景 | 系统行为 | 用户可见 |
| --- | --- | --- | --- |
| E1 | 模型超时/报错 | 停止生成，返回已有证据 | 黄色横幅 + 证据卡（结构化数据表 + "AI 分析暂不可用"声明），任务置 DEGRADED |
| E2 | 模型返回非法 JSON | 自动修复重试一次，仍失败按 E1 | 同 E1 |
| E3 | 扶摇零命中/多命中 | 零命中转开放式追询；多命中取候选 | 追询提示 / 候选列表澄清卡 |
| E4 | 词典层不可用 | 回退规则 + 大模型判定 | 无感（无横幅） |
| E5 | 画像服务不可用 | 回退会话级体验 | 无感（无横幅） |
| E6 | 会话超 30 分钟 | 会话置 EXPIRED | 过期卡，可重新提问，历史可查看 |
| E7 | 并发评测 | 第二次触发返回进行中状态 | 评测页显示进度 |
| E8 | 超长输入/提示词注入载荷 | 分隔标记包裹、超长截断 | 截断红线提示 |
| E9 | 跨站脚本载荷 | 模板自动转义 + Markdown 白名单子集渲染 | 无脚本执行 |
| E10 | iFinD 配额耗尽 | 环境与归因层证据缺口标注 | "资讯源暂不可用"标注，扶摇事实主链路不受影响 |
| E11 | 调度器异常（例行/盯盘未按计划触发） | 任务保留，触发窗口补跑；连续两个窗口失败置任务为"待手动检查" | 动态页横幅提示"调度延迟，可手动立即检查"；任务不静默丢失 |

### 2.11 提示词契约与注入防护

| 契约 | 内容 |
| --- | --- |
| P1 上下文与继承 | 追问指代解析规则、画像注入格式（标注来源）、继承字段标注规则 |
| P2 事实边界 | 数字与事实只能来自证据块并逐条引用编号；证据缺失即声明缺失；不确定信息显式标注，不得与事实混排 |
| P3 输出形态 | 四段式结构与简报四件套、中性措辞、禁用词表（涨停预测、建议买入、目标价、稳赚等） |

简报生成与动静定级受 P2/P3 同权约束。注入防护分三层。输入侧：用户输入置于分隔标记内，标注为用户原始输入而非指令（E8）。数据侧：工具返回内容（尤其新闻文本）以只读资料块注入提示词，声明其非指令来源，工具文本中的指令性语句不进入回答与简报。输出侧：输出校验器（2.7）与红线词表扫描，简报通道同样过检。

### 2.12 任务执行引擎

任务执行引擎采用"一处引擎、五入口"设计：对话问句、点子、委托、例行触发、合规转译均收敛为 research_task 实例，由同一状态机推进、同一事件流记录、同一校验器把关；入口差异仅为任务创建方式，执行语义一致。

任务状态机（research_task.state，与 2.9 会话状态机的 EXECUTING 态对应展开）：

```text
QUEUED ──调度──> PLANNING ──蓝图映射完成──> FETCHING ──全部工具返回──> VERIFYING ──校验通过──> ASSEMBLING ──生成完成且过检──> DELIVERED
   │               │                          │                │                 │
   │               └─蓝图外请求（任务域校验失败）┴─工具失败(重试1次后)──┴─数字不一致(重写1次后)──┴─红线命中──> FAILED / DEGRADED
   └─排队超限（>8 并发）：工作卡显示排队位次，不丢弃
DEGRADED = 证据卡交付（结构化数据 + 显式声明），FAILED = 可手动重跑（新实例引用原规格版本）
```

阶段事件（task_event，事件溯源）：plan_complete（含蓝图选择与理由字段）/ stage_start / stage_end / tool_call_begin / tool_call_end（含输入摘要、输出条数、耗时、状态）/ evidence_appended / llm_call（关联 ai_usage_log）/ verify_pass / verify_fail / deliver。三层监看全部由 task_event 渲染，前端零状态推算：

| 监看层 | 载体 | 内容 | 面向 |
| --- | --- | --- | --- |
| L1 过程层 | 工作卡（CH-10，对话流内） | 当前阶段徽章 + 一句话动作（"正在取数：宁德时代行情快照"）+ 已调用工具 chips + 累计耗时 | 所有用户 |
| L2 任务层 | 任务中心（TR-01） | 任务清单：类型、标的、状态、耗时、产物入口 | 关注进度的用户 |
| L3 审计层 | 工作日志（TR-05） | 全事件流：阶段、工具调用、模型调用、token、耗时、证据编号 | 审计与工程视角（评审入口） |

执行语义：PLANNING 由证据蓝图确定性映射（非模型自由规划）；FETCHING 并行取数（asyncio 并发 + 扶摇 60 秒响应缓存复用，同标的同时段多任务共享缓存）；VERIFYING 执行输出校验器（数字—证据比对 + 红线扫描）；ASSEMBLING 按 2.7 回答形态分级组装（fact_query 模板直答，其余模型受 P1–P3 约束生成四段式回答或简报）；模型故障走 DEGRADED 证据卡路径（2.10 E1）。

幂等与重试：任务提交设幂等键（问句入口为会话 ID + 问题哈希，点子与转译入口为来源 ID）；工具调用失败重试一次；FAILED 任务可手动重跑（新实例引用原规格版本，历史不覆盖）。

调度器：单容器内 asyncio 调度循环 + Redis 锁防重入（4C4G 单容器约束下不引入独立消息队列中间件）；交易日历感知（例行任务仅交易日触发，数据源为扶摇交易日历工具）；调度器异常走 E11 补跑与降级。并发上限 8 任务（超限排队并显示位次），单用户每日任务配额（默认 30 次研究 + 50 次盯盘检查，防成本失控）。

成本与可观测：每次任务的 token、工具调用、耗时经 ai_usage_log 与 tool_call 落库；任务维度成本看板（画像页不展示，运营后台可查）支撑 AR-5 成本治理。

### 2.13 持续任务与简报

持续任务覆盖盯盘值守（watch）与例行研究（routine）。

任务类型与触发：

| 类型 | 触发方式 | 内置任务 | 自定义 |
| --- | --- | --- | --- |
| watch 盯盘 | 事件触发：调度器按检查窗口（默认交易日每小时，可缩短至 15 分钟）轮询数据源，触发条件命中则创建研究任务 | 减持/质押/业绩预告等公告关键词盯守；涨跌停梯队进入/离开 | 对话委托（D11/CH-09）、点子、任务中心表单三入口创建，词表与阈值全字段可编辑 |
| routine 例行 | 定时触发：交易日历感知的定时任务 | 15:30 收盘复盘（对当日已研究标的与 watch_list）；每周五持仓体检 | 模板启停 + 标的池与深度自定义 |

触发条件确定性原则：触发由规则执行（词表命中、阈值穿越、定时到期），不由模型判断；模型仅负责命中动静的定级与行文（受 P2/P3 约束）。该原则将误报控制在工程可调范围内。

降噪与频控：同标的同日多条动静合并为一条简报；每标的每日 ≤ 1 条（用户可调，上限 3）；同类动静 7 日内不重复触发（阈值穿越类）。负反馈闭环：用户对简报选择"不重要"后，该任务的词表收紧一档（删除命中的宽泛词）或阈值放宽一档；连续三次负反馈提示用户调整委托规格。

简报契约（briefing，压缩形态的回答，合规与溯源同权）：

| 要素 | 规格 |
| --- | --- |
| 事实段 | ≤ 120 字，只陈述已发生事实，数字带角标，事实/推断徽章沿用 |
| 引用 | 角标 [n] 回链引用四要素（来源/时点/单位/口径），与回答同一协议 |
| 影响一句话 | 中性措辞的影响面提示（"该公告意味着减持上限为总股本的 2%"），禁用方向性判断词 |
| 行动入口 | "查看完整研究"→ 发起对应点子/对话承接；"不重要"→ 触发降噪 |
| 合规 | R1 红线扫描 + 输出校验器同权过检；AI 生成标识与免责行固定展示 |

简报默认为拉取式（动态页浏览）；推送通知为 V1.1 可选项，默认关闭，频控为每日全局 ≤ 3 条。


### 3.2 信息架构与导航

底部五 Tab：知音（对话，默认首页）、点子（任务货架）、动态（简报流）、盯与追（任务中心）、我的（画像 + 词条库 + 设置）。导航结构对照个人智能体范式的五板块（1.2）：聊天对应知音 Tab，点子对应点子 Tab，动态对应动态 Tab，目标（长期追踪）与文件（产出存储）在金融场景合并为盯与追（进行中的值守任务与产出归档），用户主权区（画像、词条、设置）独立为我的。会话历史收进对话页侧栏抽屉。

### 3.3 核心业务流程与 Web 原型的关系

一次典型研究交互为二至四次请求：提问或委托 →（至多两轮澄清选择）→ 确认研究规格 → 工作卡（阶段推进）→ 收到回答或简报。五径交互形态见 2.4；执行阶段为异步任务轮询/推送（2.12）。

Web 原型（24 小时交付物）为正式开发前的功能验证切片，与 App 共享同一套接口契约（33 个 JSON 接口）与状态机（2.9/2.12）；原型裁剪载体形态，机制全量实现。机制（词典、画像、决策器、规格、蓝图、合规、降级、任务引擎、调度器、简报）在原型内全量实现；App 相对原型的增量为系统推送、目标追踪、分享与新手引导（建于同一 API 之上）。数据面分层：App 为双源全量目标形态（扶摇九 + iFinD 六）；Web 原型实现 P0 子集（扶摇九 + iFinD 四，政策与跨市场两工具列入 90 天路线图）。裁剪明细、账号与预置数据方案、部署方案见《知音 Zhiyin Web 原型设计文档》。

卡片为对话页唯一组件形态：用户输入产出用户气泡，系统理解与执行产出九种卡片之一（LexiconNote、ClarifyCard、BoundaryCard、MemoryNoteBar、SpecCard、DelegateCard、WorkCard、AnswerCard、BriefingCard），卡片顺序即交互时间线；历史回放与实时交互共用同一组件。工作卡与回答卡构成过程与结果对：DELIVERED 前工作卡展开、回答卡骨架；DELIVERED 后工作卡塌缩为一行、回答卡展开。

### 5.3 全局交互规范

| 规范 | 约定 |
| --- | --- |
| 加载态 | 决策与执行阶段由工作卡承担（真实阶段推进，2.12），无全局 loading 遮罩、无示意性动画 |
| 空态 | 对话空态展示五径示例问题；动态空态展示"未来简报的样子"示例卡（FD-01）；任务空态引导三入口创建 |
| 错误态 | 网络/服务错误以卡片内重试按钮呈现；错误码与前端表现对照 E1–E11（2.10） |
| 降级态 | 降级横幅（黄色）仅影响主链路时出现（E1/E3/E10/E11），注明原因与影响范围；工作卡 DEGRADED 态黄色边框 + 显式声明；降级不静默 |
| 动效约束 | 卡片展开/塌缩 200ms；工作卡阶段切换为状态驱动（无装饰性动画）；无全屏转场 |
| 深色模式 | 跟随系统；事实/推断分色在两套主题下均保持可辨识（不依赖颜色单独编码，辅以徽章文字） |

## 6 非功能需求

### 6.1 性能

| 指标 | 要求 |
| --- | --- |
| 冷启动 | 首屏可交互不超过 2.5 秒（中端机型） |
| 卡片交互 | 澄清点选到下一卡片出现 p95 小于 3 秒（服务端决策） |
| 端到端 | 提问到回答 p95 小于 30 秒（S3）；简报触发到可读 p95 小于 60 秒 |
| 工作卡 | 阶段事件到卡片更新延迟不超过 2 秒（App 长连接 / Web 原型 2 秒轮询） |
| 调度 | 例行任务触发窗口误差不超过 60 秒（15:30 例行在 15:30–15:31 内产出）；盯盘检查窗口按委托规格执行 |
| 并发 | 单容器同时执行任务 ≤ 8，超限排队并显示位次（4C4G 约束下的背压设计） |
| 稳定性 | 崩溃率低于 0.1%；弱网（3G/丢包 30%）下请求幂等可重放 |
| 资源 | 词典本地缓存不超过 5MB；图片卡分享生成不超过 1 秒 |

### 6.2 安全与隐私

## 8 评测与验收体系

### 8.1 评测原则

评测遵循三项原则：公开（金标题目与判分标准可查）、对照（双臂与消融控制变量）、显著（以统计检验代替均值罗列）。每项机制（澄清、词典、画像、任务引擎、简报）均为可独立开关的功能，其价值须可在金标评测、工程测试与灰度实验中验证。评测分两轨：意图机制（金标评测，H1/H4/H7/H8）与任务链路（工程测试 T 组 + 灰度关系指标，S8–S10、H9–H11）。

### 8.2 金标集设计

60 题金标集（data/golden_60.csv，AI 起草后经人工逐条校对冻结，版本化管理；起草与装载流程见《知音 Zhiyin Web 原型设计文档》8.3），用于度量意图机制，结构如下：

| 组 | 题量 | 覆盖 |
| --- | --- | --- |
| 歧义组 | 30 | A1–A6 六类歧义各至少 4 题，含决策犹豫期真实问句形态 |
| 清晰组 | 15 | 财报/估值/行情事实题（检验不误触，H4） |
| 合规组 | 5 | 预测/指令/承诺类（检验红线零违例） |
| 词典组 | 10 | 黑话与别名消解（检验 H7） |

任务链路不进金标评测（其质量判据为工程正确性与灰度行为指标），由 T 组工程用例与简报抽检承担（8.6）。

### 8.3 双臂对照协议

| 项 | 基线臂 | 知音臂 |
| --- | --- | --- |
| 词典 / 画像 / 澄清 | 全关（规则直答） | 全开 |
| 回答模型、数据工具、判分模型、提示词 | 完全一致 | 完全一致 |

知音臂的澄清选择由评测代理按金标期望选项模拟（金标题目自带期望选项），故 H1 结论为机制理想路径的上限估计，澄清的真实体验质量由灰度 H5 验证；跳过率等真人交互指标不在自动评测范围。评测判分模型（deepseek-v4-pro）与研究模型（deepseek-flash，DeepSeek V4.1-Flash）分离并盲评，规避自评偏好。

### 8.4 指标与成功判据

六项金标评测指标：方向正确率、要点覆盖率、澄清触发正确率（应澄清触发/清晰题不触发）、平均交互轮次、词典消解正确率、误消解率。成功判据 S1–S10：

| 编号 | 判据 | 达标线 |
| --- | --- | --- |
| S1 | 方向正确率（金标知音臂） | ≥ 0.85 |
| S2 | 清晰题误触率 | < 10% |
| S3 | 端到端延迟 p95 | < 30 秒 |
| S4 | 词典消解正确率 / 误消解率 | ≥ 90% / < 2% |
| S5 | 澄清完成率（跳过率） | ≥ 70%（≤ 30%，灰度判据） |
| S6 | 溯源通过率（抽查 20 关键数字回链） | 100% |
| S7 | 合规红线扫描零命中 | 0 违例 |
| S8 | 持续委托率（灰度 8 周，周活用户持有进行中任务比例） | ≥ 25% |
| S9 | 盯盘任务 7 日续用率（灰度） | ≥ 40% |
| S10 | 简报误报率（用户负反馈占简报总量，灰度） | < 5%；因打扰关闭任务率 < 10% |

统计方法：金标逐题复合分配对 Wilcoxon 符号秩检验（α=0.05，scipy 实现）；敏感性检验两重：剔除极端题复跑、更换判分模型复跑，结论方向一致方为稳健。

| K2 | 澄清构成打扰：跳过率 > 50% 或澄清负反馈率 > 20% | 收紧 D8 触发阈值，仅澄清 A1/A4 类方向性歧义；其余转假设作答 |
| K3 | 消解质量不达标：词典误消解率 > 2% 持续两周 | 相关 L2 词条降级为 D4 确认式或下线，进入修正池 |
| K4 | 机制无增量价值：H1 双臂检验 p ≥ 0.05 且效应量可忽略 | 承认输入侧假设失败，转向答案侧增强评估，如实归档评测记录 |
| K5 | 简报构成噪音：误报率 > 10% 持续两周，或因打扰关闭任务率 > 30% | 相关触发条件全量下线；例行任务降频至周级；重新标定词表与阈值后再灰度 |
