## 1 原型定位与验证目标

### 1.1 原型定位

本原型对应标准产品流程（Vision → PRD → Prototype → Alpha → GA）中的 Prototype 阶段，验证对象为意图引擎（词典、画像、澄清、规格）与执行引擎（任务状态机、证据蓝图调度、持续任务、简报生成）在真实数据面与服务端账号体系下的端到端运行。原型与 App 形态（见 PRD）共享同一套接口契约（33 个 JSON 接口）、会话状态机与任务状态机：词典、画像、决策器、规格、蓝图、合规、降级、任务引擎、持续任务与简报九项机制在原型内全量实现；裁剪范围为推送、目标追踪、分享等 App 特有模块（PRD 11.3 机制对照表）。

### 1.2 验证目标

原型验证范围为 24 小时内可自动化验证的假设；需真人规模数据的假设移交灰度阶段（假设账本见 PRD 8.5）：

| 编号 | 假设 | 原型内验证方式 | 判据 |
| --- | --- | --- | --- |
| H1 | 澄清显著提升方向正确率 | 金标 60 题双臂对照 + Wilcoxon 检验 | p<0.05 |
| H4 | 清晰题不误触 | 金标清晰组对照组 | 误触率低于 10%（S2） |
| H7 | 词典消解降低澄清触发率且不损失正确率 | 金标词典组 + LEXICON_ENABLED 消融开关 | 消解正确率不低于 90%、误消解率低于 2%（S4） |
| H8 | 画像"问过一次不再问"被接受 | 画像多轮实验（同账号两问对照） | 轮次显著下降、正确率不降 |
| — | 任务引擎可运行性（工程判据，非行为假设） | T1–T6 工程用例：委托全链路、调度正确性、简报契约、生命周期、频控、降级 | T 组全过（G1 门禁） |

H2（少问曲线）、H3（留存）、H5（澄清体验）、H6（生态贡献）、H9–H11（委托关系与简报噪音）需灰度数据，不在原型验证范围；各假设的验证阶段与判据见假设账本。

### 1.3 交付范围声明

交付范围为主链路（对话五径、任务引擎与工作卡、点子、持续任务与动态、词典、画像、规格、回答、合规、评测）与五个支撑页面（金标集、评测、方法论、接口文档、登录）；不含 App 特有模块（系统推送、目标追踪、分享、新手引导，见 PRD 4.8/4.10/4.11）。

## 2 设计范围与裁剪

### 2.1 裁剪映射（App → Web 原型）

| 维度 | App（PRD） | Web 原型（本交付） | 机制是否一致 |
| --- | --- | --- | --- |
| 载体 | iOS / Android 原生 + 系统推送 | 响应式 Web（桌面优先） | 五径交互链路完全一致 |
| 执行状态传输 | 长连接推送 task_event | 2 秒轮询 task 状态接口（同一事件流，不同传输） | 状态机与事件完全一致 |
| 账号 | 同花顺账号 + 游客模式 | 本地账号（用户名 + 密码，第 6 章）：委托关系的跨会话载体 | 数据隔离与主权机制一致；登录方式为原型取舍 |
| 画像存储 | 端侧加密，画像不出设备 | 服务端独立库、按账号隔离 | 三态授权、留痕、可删可导出一致 |
| L3 私有词典 | 端侧生成与存储 | 服务端 owner_id 隔离，随画像同生命周期删除 | 一致 |
| 数据通道 | 端内直连双源 | 服务端 DataGateway 代理（密钥不出服务端） | 数据契约与降级矩阵一致 |
| 持续任务 | 全量（盯盘 2 类 + 例行 2 条） | 全量同款：检查窗口与频控规则一致；调度器为单容器 asyncio 循环 | 完全一致 |
| 推送 | 系统推送（PRD 4.10） | 不做（动态页拉取式） | 载体差异 |
| 目标追踪 | PRD TR-04 | 不做 | 明示 |

### 2.2 明确不做（本原型）与理由

| 不做项 | 理由 |
| --- | --- |
| 逐 token 流式输出（SSE/WebSocket 长连接） | 任务轮询协议（2 秒）已提供真实的阶段粒度过程流，信息粒度为研究步骤 |
| 目标追踪（TR-04）、系统推送、分享 | 与验证假设无关（PRD 1.8） |
| 实时行情图表、社区、语音输入、多轮组合问题 | 与验证假设无关 |
| 向量库与语义检索 | 词典 + 规则 + 单模型已覆盖主链路，验证期无法度量向量检索增量 |
| 独立消息队列/工作进程（Celery 等） | 4C4G 单容器约束下，asyncio 任务循环 + Redis 锁满足演示并发（≤8 并发任务），不引入额外中间件 |

裁剪原则：不支撑 H1/H4/H7/H8 验证或引擎演示的功能不做；九项机制全部保留。

## 4 核心交互流程

### 4.1 五径（演示动线）

| 路径 | 输入 | 期望行为 | 验证点 |
| --- | --- | --- | --- |
| 一（歧义题） | "新易盛还能拿吗" | 决策器判定决策支持类 + 缺周期与持仓语境 → 标的确认与周期澄清卡（两轮点选）→ 规格卡确认（可编辑）→ 工作卡阶段推进（取数→校验→组装）→ 四段式带引用回答 | 澄清机制、规格契约、真实执行过程 |
| 二（清晰题） | "贵州茅台 2026 年三季报营业收入和归母净利润是多少" | 规则层直接命中清晰模式（D2），口径声明后直答 | 不打扰（H4） |
| 三（合规题） | "明天哪只股票能涨停" | 规则层命中预测类（D1），边界卡 + 转译涨停复盘任务（扶摇涨跌停梯队与热榜真实数据），不消耗轮次 | 合规红线 |
| 四（词典+画像题） | 同一账号新会话输入"宁王这波断板了还能拿吗" | 词典三重消解（宁王→宁德时代、断板→连续涨停中断）+ 画像注入周期（D3/D5）→ 零澄清直接出规格，逐字段标注消解来源 | 词典与画像（H7/H8） |
| 五（委托题） | "帮我盯着新易盛的减持公告，有动静告诉我" | D11 委托分流 → 委托卡四要素（盯什么/何时查/什么算动静/怎么通知，可编辑）→ 确认创建 → 首次检查工作卡 → 首份简报回贴对话流，任务进入值守（动态页与任务中心可见） | 委托机制、持续任务、简报契约（T1/T3） |

### 4.2 会话状态机与任务状态机

会话九态（IDLE / DECIDE / BOUNDARY / CLARIFY / MEM_NOTE / SPEC_REVIEW / EXECUTING / ANSWERED / EXPIRED）按 PRD 2.9 执行；EXECUTING 内部展开为任务状态机（QUEUED → PLANNING → FETCHING → VERIFYING → ASSEMBLING → DELIVERED / FAILED / DEGRADED，PRD 2.12）。前端卡片渲染严格跟随接口返回的状态与卡片类型（clarify / boundary / spec / delegate / work / answer / briefing）分派，不维护副本。

### 4.3 任务化执行时序（核心协议）

```text
用户                     服务端                          数据面
 │ POST /api/chat(或 spec/confirm)                        │
 │──────────────────────────────>| 创建 research_task，   │
 │<────── 202 {task_id} ─────────│ 立即返回               │
 │ GET /api/task/{id}（2s 轮询）   │                       │
 │──────────────────────────────>| PLANNING: 蓝图映射      │
 │<──── {state, stage, action,   │ FETCHING: 并行调用 ───>│ 扶摇/iFinD
 │         tools[], elapsed} ─────│ VERIFYING: 输出校验    │<──── 证据
 │      （工作卡按此渲染推进）       │ ASSEMBLING: P1–P3 生成 │
 │──────────────────────────────>| DELIVERED              │
 │<──── {state:DELIVERED, answer} │                       │
```

提交即返回 task_id（202），前端 2 秒轮询；工作卡展示的每个阶段、每条工具调用、每秒耗时均来自 task_event 事件流，阶段为服务端真实回传，可经工作日志（L3）逐条对账。持续任务（盯盘/例行）由调度器在同一引擎内创建任务实例，产出简报入动态页，协议复用。

注：澄清、边界与规格路径不创建研究任务，POST /api/chat 直接返回对应卡片态，规格确认后才进入本图的任务化时序；委托类确认后创建持续任务，首次检查即本图的一个任务实例，其 DELIVERED 交付物为简报（回贴契约见 8.4）。

### 4.4 持续任务时序

```text
调度器（asyncio 循环 + Redis 锁）
 │ 到达检查窗口（盯盘：交易日每小时；例行：交易日 15:30）
 │──> 取该任务触发条件（词表/阈值/定时）
 │──> 条件命中 ──> 创建 research_task（standing_watch / routine_review）
 │                    └── 同一引擎执行 → 简报生成 → R1 红线扫描 + 输出校验器过检
 │                          ├── 过检 ──> briefing 落库 → 动态页可读（T3：60 秒内）
 │                          └── 失检 ──> 任务 FAILED，简报不入流（宁缺毋假，日志可查）
 └── 频控与降噪：同标的同日合并；每标的每日 ≤ 1 条；7 日内同类不重复
```

## 5 页面详细设计

### 5.1 对话页（/）

布局：

```text
┌──────────────────────────────────────────────┐
│ HeaderNav：知音 · 历史 · 点子 · 动态 · 盯与追 · 画像 · [金标集·评测·方法论] │
├──────────────────────────────────────────────┤
│ MessageStream（滚动区，消息按时间线排列）                  │
│  UserBubble / LexiconNote / ClarifyCard /       │
│  BoundaryCard / MemoryNoteBar / SpecCard /      │
│  DelegateCard / WorkCard / AnswerCard /         │
│  BriefingCard / SystemBanner（条件）              │
├──────────────────────────────────────────────┤
│ Composer：输入框（≤1000字）· 字数 · 发送              │
└──────────────────────────────────────────────┘
```

卡片交互规则：

| 卡片 | 规则 |
| --- | --- |
| UserBubble | 右对齐；原文展示不转义为富文本 |
| LexiconNote | 内联提示条"X 已按词典理解为 Y（代码）"，点击词条开释义卡浮层；提供一键改回入口 |
| ClarifyCard | 单选选项按钮（2–4 个）+ 跳过链接（skippable 时）+ 轮次指示"第 n/2 轮"；点选后塌缩为"已选择：X"；novice 画像时选项下附一句话解释 |
| BoundaryCard | 红线声明 + 转译任务卡 +「按此研究」按钮；无选项 |
| MemoryNoteBar | 三按钮「记住 / 仅本次 / 别记」，默认高亮"仅本次"；三秒无操作自动按"仅本次"处理；选择后塌缩 |
| SpecCard | 白名单字段行内编辑，改动高亮；消解来源徽章逐字段展示；底部"本次不使用画像"开关与「确认执行」 |
| DelegateCard | trigger 四要素行内编辑（词表 chips 增删、窗口下拉、通知默认仅动态页）+ 频控展示；「确认委托」后创建任务，工作卡立即出现 |
| WorkCard | 阶段徽章（排队/规划/取数/校验/组装/已交付/降级/失败）+ 当前动作一句话 + 已调用工具 chips + 耗时；2 秒轮询推进；点击展开任务摘要（蓝图选择、证据条数）；「查看日志」入口（L3）；DELIVERED 后塌缩为一行 |
| AnswerCard | 形态按 PRD 2.7 分级：fact_query 直答（口径声明 + 数据事实卡），其余研究类四段折叠；角标 [n] 悬停弹出引用卡（来源/时点/单位/口径）；事实蓝徽章、推断灰徽章；置信度分档徽章与判据一句话；缺口显式标注；底部有用/需改进按钮、AI 生成标识、免责行 |
| BriefingCard | 简报四件套：事实段（带角标）+ 影响一句话 + 行动入口（"查看完整研究"预填发起）+「这条不重要」反馈；值守首报带"已开始值守"声明行 |
| SystemBanner | 黄色横幅，降级时置顶出现，注明降级原因与影响 |

### 5.2 点子页（/ideas）

8 个点子卡（与 App 同一配置文件 data/ideas.yaml）：持有体检、涨停复盘、板块扫描、资金透视、财报速读、解套研究、新股开板复盘、指数环境体检。每卡含图标、名称、一句话说明、适用人群、预计耗时与数据面；点击进入仅需选/输标的（watch_list 芯片可选），其余字段带默认值（继承画像）→ 复用对话页规格卡组件确认 → 工作卡与回答卡同对话路径。iFinD 配额不足时资金透视与板块扫描置灰并提示（E10 预防）。

### 5.3 动态页（/feed）

| 区块 | 设计 |
| --- | --- |
| 简报流 | 时间线倒序：盯盘产出 / 例行复盘 / 异动简报；每条含类型徽章、标的、时间、事实段摘要；点击展开简报卡全文与引用 |
| 冷启动 | 无任务无简报时展示三张示例简报卡（显式标注"示例"），点击可直接创建对应任务 |
| 反馈 | 简报卡底部「有用 / 这条不重要」；不重要触发降噪（词表收紧一档）并提示 |

### 5.4 盯与追页（/tasks）

| 区块 | 设计 |
| --- | --- |
| 进行中任务 | 任务卡：类型徽章（盯盘/例行）、标的、状态（值守中/待手动检查）、最近检查时间、产出数、操作（暂停/编辑条件/删除/立即检查） |
| 创建入口 | 「新建盯盘任务」结构化表单（与 DelegateCard 同一 Schema 与接口）；例行任务开关（收盘复盘默认开、周度体检默认关） |

| 工作日志 | 任务卡「查看日志」进入：task_event 全事件流时间线（阶段、工具调用含耗时与状态、模型调用、校验结果），可展开、可导出 JSON |

### 5.5 画像页（/profile）

| 区块 | 设计 |
| --- | --- |

## 6 账号与预置数据方案

### 6.1 账号制设计依据

原型采用账号制而非匿名访客制，依据如下：持续任务、画像与简报为跨会话资产，匿名标识无法承载跨会话委托关系；预置熟客账号与新建账号分别验证用户生命周期两端（熟客态与冷启动）。原型账号为用户名 + 密码（bcrypt 哈希），不接入手机、邮箱或第三方登录；正式产品复用同花顺账号（PRD 4.9），两者不冲突。

### 6.2 账号设计

| 项 | 规格 |
| --- | --- |
| 注册 | 用户名（3–20 字符）+ 密码（≥8 位，bcrypt cost=10）；无手机/邮箱/验证码依赖 |
| 会话 | 服务端 session（Redis，TTL 7 天），HttpOnly + SameSite=Lax Cookie；登出即销毁 |
| 限流 | 每 IP 每日注册 ≤ 3 个（防灌）；登录失败 5 次锁定 10 分钟 |
| 隔离 | 全部业务表以 user_id 外键隔离（二十一表，PRD 11.2）；L1/L2 词典全局共享，L3 与画像、任务按账号隔离 |
| 合规 | 注册页展示服务协议与隐私声明摘要（不采集真实身份信息；demo 数据为构造演示数据）；不采集手机号与邮箱 |

### 6.3 预置数据：demo 熟客态 + 冷启动态

## 8 技术方案

### 8.1 架构与选型

技术栈：Python 3.11 · FastAPI · SQLAlchemy 2 (async) · MySQL（共用实例，宿主机 3307，独立库 zhiyin_db，二十一表，见 PRD 11.2）· Redis（共用实例 db 3：登录会话、限流、缓存、评测锁、调度锁）· Jinja2 模板 + 原生 JavaScript（无构建链）· scipy（Wilcoxon）· passlib[bcrypt]（密码哈希）。

模型：deepseek-flash（DeepSeek V4.1-Flash，意图判定 / 澄清生成 / 回答与简报生成，研究模型）+ deepseek-v4-pro（评测判分，与研究模型分离并盲评）；经 OpenAI 兼容适配层接入，模型可替换（适配层为唯一耦合点）。

选型理由（面向 24 小时窗口与 4C4G 约束的取舍）：

| 选型 | 替代方案 | 取舍理由 |
| --- | --- | --- |
| FastAPI + async IO 单体 | Next.js/Node 全栈 | Python 单体一条命令起服务；评测（scipy/Wilcoxon）与后端同语言；无 Node 构建链 |
| Jinja2 + 原生 JS | React/Vue SPA | 十页面无复杂前端状态；卡片渲染按接口 type 分派 + 2 秒轮询即可；零构建、零 node_modules，契合内存约束 |
| asyncio 任务循环 + Redis 锁 | Celery + 独立 worker | 单容器约束下不新增进程/中间件；≤8 并发任务的演示负载 asyncio 足够；可观测性更好（事件直接落库） |
| 服务端轮询（2s） | SSE/WebSocket | 长连接的收益为节省轮询请求，代价为连接管理与代理配置复杂度；阶段粒度（秒级）下轮询足够，且经 Nginx 零额外配置 |
| MySQL + Redis 共用实例 | 独立中间件容器 | 共用服务器规范禁止新起中间件容器（内部规范，约束取值已内联第 10 章） |

仓库目录结构见仓库 README「技术架构」一节。

### 8.2 任务化执行引擎（服务端核心，PRD 2.12 的原型实现）

| 模块 | 实现要点 |
| --- | --- |
| 任务创建 | 五入口统一收敛为 research_task（接口映射见 8.4）：chat（问句/委托）、idea/launch、boundary/translate、standing 创建、routine 触发（调度器内部）；幂等键：问句入口 session_id+question_hash，点子/转译入口 source_id；202 + task_id 即返 |
| 状态推进 | asyncio 任务协程按 PLANNING→FETCHING→VERIFYING→ASSEMBLING 推进；每次状态变更与工具调用写 task_event（阶段、动作、耗时、关联 tool_call/ai_usage_log/evidence） |
| 并发控制 | 信号量 Semaphore(8)；超限任务 QUEUED 并记录排队位次；单用户日配额（研究 30 + 检查 50）Redis 计数 |
| 数据面 | 扶摇九工具 + iFinD 四工具，蓝图确定性调度（PRD 2.6）；并发取数（asyncio.gather）；扶摇 60 秒响应缓存（同标的多任务共享） |
| 校验器 | 数字—证据比对、红线词表扫描；失败重写一次，再失败走 DEGRADED 证据卡交付 |
| 调度器 | asyncio 循环：盯盘检查窗口（默认交易日每小时）与例行定时（15:30、周五）；交易日历来自扶摇工具，故障按周一至五兜底并标注；Redis 锁防重入；异常走 E11（补跑 + 待手动检查态） |
| 简报生成 | 触发为确定性规则（词表/阈值），定级与行文由模型执行（P2/P3 约束）；过检入 briefing 表，失检不入流（T6） |
| 可观测 | task_event 为工作卡/任务中心/工作日志的唯一渲染源；ai_usage_log 记录模型调用；三者 ID 互链可对账 |

### 8.4 接口清单（33 个）

接口通用约定：

- 鉴权：除 /api/auth/* 与页面路由外均需登录（HttpOnly + SameSite=Lax Cookie 会话，6.2）；
- 响应包络：`{code, message, data}`，code=0 成功，非 0 为错误码；
- 分页：GET 列表接口统一 page/size 参数，返回 `{items, total}`；
- 时间：ISO 8601，UTC+8。

| 分组 | 接口 | 说明 |
| --- | --- | --- |
| 账号（3） | POST /api/auth/register · login · logout | 注册/登录/登出（第 6 章） |
| 会话（2） | GET /api/sessions · GET /api/session/{id}/history | 会话列表（历史侧栏抽屉）；会话消息流回放（含卡片终态与简报卡） |
| 对话（3） | POST /api/chat · POST /api/clarify/{id}/choice · POST /api/clarify/{id}/memory | 提问/委托入口（无 session_id 自动创建会话；按决策器返回卡片态 clarify/boundary/spec/delegate/work）；澄清选择；记忆确认 |
| 规格（2） | GET /api/spec/{id} · POST /api/spec/{id}/confirm | 规格获取 / 编辑确认；确认按 task_type 分流：一次性任务创建 research_task（202 + task_id），委托类创建持续任务并立即执行首次检查（返回 task_id 与 standing_task_id） |
| 任务（4） | GET /api/task/{id}（轮询）· GET /api/task/{id}/events · POST /api/task/{id}/retry · GET /api/tasks | 任务状态（工作卡渲染源）；事件流（工作日志，导出即下载该 JSON）；重跑；任务列表 |
| 点子（2） | GET /api/ideas · POST /api/idea/{id}/launch | 货架配置（含置灰状态）；点子发起——按所选标的生成预填规格，复用规格卡确认流 |
| 边界转译（1） | POST /api/boundary/{id}/translate | 边界卡「按此研究」——生成转译任务规格并进入规格确认（不消耗澄清轮次） |
| 持续任务（4） | GET/POST /api/standing · PATCH/DELETE /api/standing/{id} | 列表/创建（表单与委托卡同 Schema）/编辑（暂停恢复、条件）/删除 |
| 动态（2） | GET /api/feed · POST /api/briefing/{id}/feedback | 简报流分页；反馈（降噪入口） |
| 画像（4） | GET /api/profile · PATCH /api/profile/field/{key} · DELETE /api/profile · GET /api/profile/export | 读取 / 授权与值更新 / 删除 / 导出 |
| 词典（2） | GET /api/lexicon · POST /api/lexicon/submit | 词条检索 / 新词提交 |
| 评测（3） | GET /api/eval/golden · POST /api/eval/run · GET /api/eval/status/{batch_id} | 金标 60 题题库（金标集页与评测同源）；双臂评测触发（请求体可携带消融开关覆盖项）与轮询 |
| 记录（1） | GET /api/ai-usage/export | AI 使用记录 CSV 导出 |

五入口与任务创建的接口映射（PRD 2.12"一处引擎，五入口"的落点）：问句与对话委托 → POST /api/chat；点子 → POST /api/idea/{id}/launch；边界转译 → POST /api/boundary/{id}/translate；盯盘表单与委托确认 → POST /api/spec/{id}/confirm 与 POST /api/standing；例行触发 → 调度器内部创建（无对外接口）。

交付物回贴契约：GET /api/task/{id} 在 DELIVERED 时返回 deliverable（类型 answer 或 briefing 及其引用）；前端按 deliverable 类型渲染回答卡或简报卡，简报同步落会话消息流并进入动态页——委托路径"首份简报回贴对话流"（T1）由此契约支撑。

错误码：40001 输入超限 · 42901 限流 · 40401 会话/任务不存在 · 40402 未登录 · 50301 数据库不可用；模型/数据源/调度器故障不报错，走显式降级路径（E1–E11，前端表现见第 9 章）。

| 安全渲染 | Jinja2 自动转义；Markdown 仅渲染白名单子集（标题、加粗、列表、角标），安全渲染函数约 40 行 |
| API-first | 页面为薄壳，33 个接口全部 JSON 契约；App 复用同一契约 |
| 状态跟随 | 前端不维护业务状态机副本；卡片渲染按接口 type 分派；工作卡仅消费 task 状态接口返回，零推算 |
| 轮询纪律 | 仅两类轮询：任务状态 2 秒（DELIVERED/FAILED 即停）、评测进度 5 秒；页面不可见时暂停（visibilitychange） |

### 8.6 成本预算

| 项 | 估算 | 说明 |
| --- | --- | --- |
| 评测一次（60 题 × 双臂） | 模型成本约 4–8 元；6–18 分钟后台运行 | 判分模型与研究模型分离 |
| iFinD 消耗 | 评测约 240–280 次（双臂同工具面）+ 盯盘值守约 15–30 次/日（交易日小时级检查窗口 × 2 任务 × 每次检查 1–2 次调用，含例行复盘） | 体验版 2000 次配额；评测前自动检查余量，低于 300 次时宽度与资金降频至决策类题目（E10 预防） |
| 主链路日常演示 | 忽略不计 | Flash 档模型定价；60 秒扶摇缓存复用 |
| 服务器 | 零新增成本 | 复用既有 4C4G 共用实例，不新购 |

## 9 状态与异常设计

全部异常显式降级，不静默生成结论。异常定义与系统行为按 PRD 2.10 降级矩阵 E1–E11 执行，本节定义前端表现，与故障注入用例一一对应：

| 异常场景 | 前端表现 |
| --- | --- |
| 模型超时/报错（E1） | 降级横幅 + 证据卡（结构化数据表 + "AI 分析暂不可用"声明）；工作卡终态 DEGRADED |
| 模型返回非法 JSON（E2） | 自动修复重试一次；仍失败按 E1 展示 |
| 扶摇零命中/多命中（E3） | 开放式追询提示 / 候选列表澄清卡 |
| 词典层不可用（E4） | 无感回退规则 + 大模型判定（无横幅） |
| 画像服务不可用（E5） | 无感回退会话级体验（无横幅） |
| 会话超 30 分钟（E6） | 过期提示卡片，可重新提问；历史可查看；持续任务不受影响 |
| 并发评测（E7） | 第二次触发返回"进行中"状态 |
| 超长输入/注入载荷（E8） | 截断并红线提示 |
| 跨站脚本载荷（E9） | 模板自动转义 + Markdown 白名单子集渲染，无脚本执行 |
| iFinD 额度耗尽（E10） | 环境与归因证据缺口标注"资讯源暂不可用"，个股事实（扶摇）主链路不受影响；点子页相关卡片置灰 |
| 调度器异常（E11） | 动态页横幅"调度延迟"；受影响任务置"待手动检查"并显示「立即检查」按钮；任务不静默丢失 |
