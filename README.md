# 知音 Zhiyin（zhiyin）

> 投资者的个人研究智能体：听得懂、干得完、盯得住、记得住、有分寸——把你的研究接过去。

知音承接个人投资者的研究工作流：一句话、一个点子或一条委托即可发起研究；知音理解意图（必要时澄清，澄清频次随使用递减），按用户确认的规格调度数据工具执行，交付带来源、正反论点齐备的研究框架；对盯盘与例行任务长期值守，以简报主动汇报。产品为同花顺生态副产品，不设独立盈利目标；完整产品定义见[项目文档体系](#项目文档体系)。

## 背景

A 股 2.51 亿个人投资者（中国结算 2025 年报口径）中，绝大多数持仓市值低于百万、无投顾覆盖。其研究行为具有两个特征：提问形态为口语、黑话与隐含持仓语境（"宁王这波断板了还能拿吗"）；工作流为持续循环（盘中盯公告与异动、异动后查证、持仓定期体检、盘后复盘）。当前 AI 投研产品（问财、千问财经分析、Kimi、Wind AI 等）的能力建设集中于答案生成侧，交互仍为问答工具；个人智能体范式（Meta Muse：任务委托、过程可见、记忆、主动服务，公开报道见 PRD 11.4）已在生活场景验证，在金融证券场景仍属空白。

知音为金融证券场景的个人智能体变体：保留任务委托与过程透明的范式，叠加金融场景约束（不预测不荐股、关键数字可溯源、决策权在用户）。差异化内核为意图引擎（三层词典、投资者画像、澄清、研究规格），执行骨架为任务化引擎（证据蓝图、持续任务、简报），机制效果由 60 题金标集双臂对照实验度量。

## 功能特性

**意图引擎（听得懂）**

- **三层领域词典**：L1 标准金融语 / L2 社区黑话与别名（宁王→宁德时代）/ L3 用户私有词汇；命中即毫秒级消解，零交互成本
- **投资者画像**：字段级三态授权（记住 / 仅本次 / 别记），问过一次不再问；画像页可见、可改、可删、可导出，每次应用留痕
- **Clarify-or-Delegate 三层决策器**：词典 → 规则 → 大模型；六类歧义识别（A1–A6），决策表 D1–D11 纯函数可审计；五径分流（歧义 / 清晰 / 合规 / 词典画像 / 委托）
- **研究规格（Research Spec）**：人机确认断点；逐字段标注消解来源（词典 / 画像 / 澄清 / 假设）

**执行引擎（干得完、盯得住）**

- **任务化执行引擎**：五入口（问句/点子/委托/例行/转译）统一收敛为研究任务；状态机 QUEUED→PLANNING→FETCHING→VERIFYING→ASSEMBLING→DELIVERED + task_event 事件溯源；执行真实可查，非动画示意
- **三层监看**：工作卡（过程层，对话流内实时阶段）/ 任务中心（任务层）/ 工作日志（审计层：工具调用、token、耗时全事件流）
- **持续任务与调度器**：盯盘（词表命中、阈值穿越的事件触发）+ 例行（交易日 15:30 收盘复盘、周五持仓体检）；触发为确定性规则，模型仅做动静定级与行文
- **简报契约**：盯盘与例行产出的事实卡（≤120 字带角标 + 引用四要素 + 中性影响一句 + 行动入口）；R1 红线与输出校验器同权过检，校验失败不入流（宁缺毋假原则）；同标的同日合并、每日每标的 ≤ 1 条、负反馈自动收紧阈值

**研究交付（有分寸、可度量）**

- **带引用回答**：研究类任务为四段式（结论摘要 / 事实与正方论点 / 反方论点与风险 / 未覆盖与假设），fact_query 为直答形态（口径声明 + 数据事实卡，不调模型）；引用含来源、时点、单位、口径四要素；事实与推断分色徽章；置信度按确定性规则分档
- **证据蓝图与双源工具调度**：任务类型确定性映射工具组合（扶摇九工具：个股事实面；iFinD 四工具：市场环境与归因面），调用路径可审计
- **点子货架**：8 个预置研究任务（持有体检 / 涨停复盘 / 板块扫描 / 资金透视 / 财报速读 / 解套研究 / 新股开板复盘 / 指数环境体检），预设规格起点一键委托
- **合规转译**：预测类与买卖指令类问题返回边界卡并转译为可执行研究任务，不输出涨跌预测；简报文案同受红线约束
- **金标评测**：60 题金标集双臂对照（基线 vs 知音机制）+ Wilcoxon 显著性检验 + 词典 / 画像 / 调度器消融开关，产品内一键复跑
- **全链路降级**：模型、词典、画像、数据源、调度器故障均显式降级（E1–E11：证据卡 / 回退 / 缺口标注 / 待手动检查），不静默生成结论

## 快速开始

### 环境要求

- Docker + Docker Compose
- 共用中间件（服务器既有实例）：MySQL 8（宿主机 3307）、Redis 7（本产品用 db 3）
- 外部密钥：扶摇 API Key、DeepSeek API Key（iFinD MCP 可选，留空自动降级，不影响主链路）

### 安装与运行

```bash
# 1. 克隆仓库
git clone <repo-url> && cd zhiyin

# 2. 建库建用户（一次性，共用 MySQL 实例）
mysql -h 127.0.0.1 -P 3307 -u root -p < scripts/init_db.sql

# 3. 配置环境变量（仓库不含任何真实密钥）
cp .env.example .env && vi .env

# 4. 构建并启动（容器内存 512m / CPU 1.0，按部署规范强制配额）
docker compose up -d --build

# 5. 导入种子数据（词典 400 词条落库 + 金标 60 题装载 + 底稿校验）
docker exec zhiyin-fastapi python scripts/seed.py

# 6. 生成 demo 熟客态（真实引擎回放：会话 2 / 任务 2 / 简报 5，非手写 JSON）
docker exec zhiyin-fastapi python scripts/seed_demo.py

# 7. 配置 Nginx 反向代理（conf/nginx/zhiyin.conf → listen 8083）并 reload

# 8. 验证
curl http://127.0.0.1:8083/healthz
# 预期 {"status":"ok","db":"ok","redis":"ok","lexicon":400,"scheduler":"on","demo":"ready"}
```

### 环境变量

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `DATABASE_URL` | MySQL 连接串（独立库 zhiyin_db） | — |
| `REDIS_URL` | Redis 连接串（db 3） | — |
| `FUYAO_API_KEY` / `FUYAO_BASE_URL` | 扶摇 API（行情/财报/K线/估值/成分/日历/涨跌停/热榜） | — |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 研究模型（OpenAI 兼容适配层，可替换） | deepseek-flash（DeepSeek V4.1-Flash） |
| `JUDGE_MODEL` | 评测判分模型（与研究模型分离并盲评） | deepseek-v4-pro |
| `IFIND_MCP_URL` / `IFIND_API_KEY` | iFinD MCP（新闻/宏观/市场宽度/资金流向；留空自动回退） | 空 |
| `LEXICON_ENABLED` / `PROFILE_ENABLED` | 词典 / 画像层开关（降级与消融实验共用同一实现） | true |
| `LLM_ENABLED` | false 时强制纯规则模式（演练 / 兜底） | true |
| `SCHEDULER_ENABLED` | false 时持续任务降级为"手动立即检查"（E11 演练 / 调度器隔离调试） | true |

## 评测复现

```bash
# 产品内一键触发（或访问 /eval 页面点击"运行评测"）
curl -X POST http://127.0.0.1:8083/api/eval/run
# 轮询进度与结果
curl http://127.0.0.1:8083/api/eval/status/{batch_id}
```

- 双臂设计：基线臂关闭词典 / 画像 / 澄清，知音臂全开；回答模型、数据工具、判分模型、提示词完全一致
- 产出六指标对照（方向正确率、要点覆盖率、澄清触发正确率、平均交互轮次、词典消解正确率、误消解率）、逐题复合分 Wilcoxon 检验（α=0.05）、敏感性检验、画像多轮实验

- 指标解读：方向正确率为价值指标；平均交互轮次为代价指标；清晰题误触率与词典误消解率为护栏
- 评测假设账本（H1–H11）：本原型验证 H1/H4/H7/H8 与任务链路工程判据（T 组）；H2/H3/H5/H6/H9–H11 需灰度数据（定义见 PRD 第 8 章）

## 技术架构

- **栈**：Python 3.11 · FastAPI · SQLAlchemy 2 (async) · MySQL（独立库 zhiyin_db，二十一表）· Redis db 3（登录会话、限流、缓存、评测锁、调度锁）· Jinja2 + 原生 JavaScript（无构建链）· scipy（Wilcoxon）· passlib[bcrypt]
- **模型**：deepseek-flash（DeepSeek V4.1-Flash，意图判定 / 澄清生成 / 回答与简报生成）+ deepseek-v4-pro（评测判分，与研究模型分离并盲评）；OpenAI 兼容适配层，模型可替换
- **引擎**：任务化执行引擎（asyncio 任务协程 + Semaphore(8) 背压 + task_event 事件溯源）；调度器为单容器 asyncio 循环 + Redis 锁 + 交易日历感知（4C4G 约束下不引入独立消息队列）
- **部署**：单容器 zhiyin-fastapi（内存 512m / CPU 1.0），宿主机 Nginx 入口 8083，后端映射 8014；遵循共用服务器端口与隔离规范（下一可用位零冲突、零新增中间件容器）

```text
zhiyin/
├── app/
│   ├── main.py            # FastAPI 实例、中间件、healthz、调度器启动
│   ├── api/               # auth / session / chat / clarify / boundary / spec / task / standing / feed / idea / profile / lexicon / eval / pages
│   ├── services/          # clarify · lexicon · profile · spec · engine(任务状态机) · scheduler(调度器) · briefing · evaluate
│   ├── llm/client.py      # OpenAI 兼容适配层 + ai_usage_log
│   ├── tools/             # fuyao（九工具）/ ifind（四工具）/ dossier（底稿）/ blueprint（证据蓝图）
│   ├── templates/         # 十页面（login / 对话 / ideas / feed / tasks / profile / golden / eval / about / docs）
│   └── static/            # app.js · style.css
├── scripts/               # init_db.sql · seed.py · seed_demo.py（引擎回放）· draft_golden.py（金标 AI 起草辅助）
├── data/                  # golden_60.csv（金标 60 题）· lexicon_seed.csv（词典种子 400 词条）· dossier/（预置底稿五家）· ideas.yaml（点子 8 个）
├── tests/                 # F/LX/PF/E/C/T 六组用例（共 47 条）
```

## API 概览

33 个 JSON 接口，完整 schema 见运行后 `/docs`（框架自动生成，为 API-first 设计的对外佐证）。通用约定：除 /api/auth/* 与页面路由外均需登录（HttpOnly + SameSite=Lax Cookie 会话）；响应包络 `{code, message, data}`；列表接口统一 page/size 分页；时间 ISO 8601（UTC+8）。

| 分组 | 接口 | 说明 |
| --- | --- | --- |
| 账号（3） | POST /api/auth/register · login · logout | 账号（委托关系的跨会话载体，demo 预置熟客态） |
| 会话（2） | GET /api/sessions · GET /api/session/{id}/history | 会话列表（历史抽屉）· 会话消息流回放（含卡片终态与简报卡） |
| 对话（3） | POST /api/chat · POST /api/clarify/{id}/choice · POST /api/clarify/{id}/memory | 提问/委托入口（自动建会话，按决策器返回卡片态）；澄清选择；记忆确认（记住 / 仅本次 / 别记） |
| 规格（2） | GET /api/spec/{id} · POST /api/spec/{id}/confirm | 研究规格获取 / 编辑确认（一次性任务即建任务 202 + task_id；委托类创建持续任务并立即执行首次检查） |
| 任务（4） | GET /api/task/{id} · GET /api/task/{id}/events · POST /api/task/{id}/retry · GET /api/tasks | 任务状态轮询（工作卡渲染源，2 秒）；事件流（工作日志）；重跑；任务列表 |
| 点子（2） | GET /api/ideas · POST /api/idea/{id}/launch | 点子货架（含数据源健康置灰状态）· 点子发起（生成预填规格） |
| 边界转译（1） | POST /api/boundary/{id}/translate | 边界卡「按此研究」生成转译规格（不消耗澄清轮次） |
| 持续任务（4） | GET/POST /api/standing · PATCH/DELETE /api/standing/{id} | 列表 / 创建（表单与委托卡同 Schema）/ 编辑（暂停、条件）/ 删除 |
| 动态（2） | GET /api/feed · POST /api/briefing/{id}/feedback | 简报流分页 · 反馈（降噪闭环入口） |
| 画像（4） | GET /api/profile · PATCH /api/profile/field/{key} · DELETE /api/profile · GET /api/profile/export | 读取 / 授权与值更新 / 一键删除 / 导出（含 L3 词条与任务定义） |
| 词典（2） | GET /api/lexicon · POST /api/lexicon/submit | 词条检索 / 新词提交 |
| 评测（3） | GET /api/eval/golden · POST /api/eval/run · GET /api/eval/status/{batch_id} | 金标 60 题题库 · 双臂评测触发（支持消融开关覆盖项）与轮询 |
| 记录（1） | GET /api/ai-usage/export | AI 使用记录 CSV 导出 |

错误码：40001 输入超限 · 42901 限流 · 40401 会话/任务不存在 · 40402 未登录 · 50301 数据库不可用；模型 / 数据源 / 调度器故障不报错，走显式降级路径（E1–E11，见 PRD 2.10）。

| 领域词典（data/lexicon_seed.csv） | 首批 400 词条（L1 150 + L2 250），AI 起草 + 人工逐条校对定稿 | 词条级来源与审核人落库，版本可回滚 |

全部关键数字遵循引用四要素协议（来源 / 时点 / 单位 / 口径），回答与简报同权；数据缺失、冲突、过期或调用失败时显式标注，不静默生成"正常"结论。demo 账号数据为引擎回放生成的构造演示数据，无真实用户数据。

## AI 的角色与使用记录

- **人机分工**：
  - 词典释义与金标题目由 AI 起草，人工逐条校对定稿，校对差异全量留痕
  - 意图判定、澄清生成、回答与简报生成由模型执行，受决策表 D1–D11 与提示词契约 P1–P3 约束，数字只能来自证据材料
  - 持续任务触发为确定性规则（词表/阈值/定时），模型仅做动静定级与行文
  - 评测判分模型与研究模型分离并盲评
  - 设计立场：模型负责语义，规则负责边界，引擎负责过程；高频黑话消解与清晰题直答走词典与规则层（不调模型），长尾语义理解与研究框架生成使用模型，工具组合由证据蓝图确定性映射（计划确定性 Agent，非自由规划）
- **使用记录**：每次模型调用写入 ai_usage_log（用途、模型、token、延迟、状态），每次任务执行写入 task_event 与 tool_call（阶段、工具、耗时），`GET /api/ai-usage/export` 导出 CSV，为"AI 使用与验证记录"交付物的数据源
- **修正记录**：AI 起草内容的人工校对差异、评测中发现的模型错误输出与修正方式，记录于 `docs/AI_USAGE.md`

## 已知边界与未做事项

- 不做逐 token 流式输出（任务 2 秒轮询已提供真实阶段流）、系统推送（动态页拉取式）、目标追踪与分享（定义见 PRD，不在本原型范围）
- 任务域封闭：不做证据蓝图外任务的自由执行；预测与买卖指令类问题转译为研究任务（R1 红线）
- iFinD 政策与跨市场两工具未进 P0；体验版配额管理与评测余量检查见[评测复现](#评测复现)
- 深度研究证据依赖预置底稿（五家公司，扶摇真实快照冻结）+ 扶摇全市场数据面，不做全市场深度研究
- Web 原型账号为本地账号（用户名+密码，验证隔离与委托载体）；画像存储为服务端账号隔离，端侧加密方案见 PRD 4.9
- 演示环境公网链路为 HTTP（端口与部署规范约束）；生产形态按 PRD 6.2 全链路 TLS 1.2+ 执行
- 简报质量的行为判据（误报率 S10、续用率 S9）需灰度数据，原型内以 T 组工程判据与合规抽检替代

## 合规声明

- **内容红线**：不输出涨跌预测、买卖建议、收益承诺；决策类问题转译为研究任务；简报文案同受 R1 红线约束（对应证监会公告〔2012〕40 号对"荐股软件"功能的界定；产品定性为研究工具，非投资咨询）
- **AI 标识**：全部 AI 生成内容（含简报）带显式标识；导出保留标识字段（《人工智能生成合成内容标识办法》，2025 年 9 月施行）
- **画像底线**：不采集金融账户、身份证明、联系方式、精确资产数额；字段级三态授权、可删可导出、应用留痕；不用于模型训练、不跨用户共享、不用于差异化定价（个保法第 24 条，自动化决策可拒绝）
- **词典治理**：发布必经人工审核；策略类词条强制风险提示语；释义禁用收益暗示措辞
- **打扰配额**：澄清硬上限 2 轮；简报同标的同日合并、每标的每日 ≤ 1 条；动态页拉取为默认形态，无系统推送
- **免责五要素**：仅供参考不构成投资建议；风险提示且不承诺收益；标注来源与时点；AI 生成显著标识；不作为买卖依据、据此操作风险自担
